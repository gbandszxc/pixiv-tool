# ADR 0036：翻译运行层窗口防护与任务续跑

- 状态：已接受（细化 [ADR 0035](0035-whole-novel-agent-translation.md) 的运行层行为；不推翻其决策）
- 日期：2026-10-25
- 关联 ADR：[ADR 0033](0033-translation-dynamic-output-cap-and-default-thinking.md)、[ADR 0034](0034-rig-agent-kernel-and-rust-toolchain.md)、[ADR 0035](0035-whole-novel-agent-translation.md)
- 规格：[SPEC](../SPEC.md) §4.3

## 背景

真实故障（2026-10-25，一篇 1 页 6 块的短篇、两个模型先后失败）暴露了运行层的两个缺陷：

1. **单轮并行读块拉爆窗口**。协调者模型一次并行调用全部 `read_chunk`（6 块 × 块内容 + 邻接窗口 ≈ 32k tokens），一次性进入下一轮请求的 prompt。上下文压缩器只覆盖 rig-agent 传入的 `history`（每轮最后一条消息作为 prompt 单独传入），对 prompt 内的工具结果无能为力；压缩器看到的历史只有约 900 tokens，报「没有可压缩的历史」，随后窗口检查直接以 `input_too_large` 终止任务。
2. **模型提前收工任务即停**。另一模型在第 5 轮输出纯文本（不再调用工具），本轮运行正常结束；服务层只执行一次 `runtime::run`，完成校验不通过就直接转 `needs_attention`（incomplete），没有任何续跑机制，任务停在准备阶段直到用户手动取消。

提示词约束（如「单轮最多读 2 块」）不能作为防线——模型行为不可控，运行层必须自行设防。

## 决策

### 1. 单轮工具结果预算（第一道防线）

- 运行层在 `on_dispatch` 钩子按「工具名 + 参数」预估每个工具调用的结果 token（`ToolResultEstimator`，由翻译服务提供：`read_chunk` 按块字符数 + 邻接窗口 + 结构开销估算，其余工具返回 0 不参与）。
- 单轮（两次模型调用之间）累计预估量超过预算时，拒绝执行剩余调用（`DispatchAction::skip`），模型收到跳过原因并在下一轮分批读取；已执行的结果不回滚。
- 预算公式：`可用输入 − 固定开销（系统提示 + 工具 schema）− 历史保留（2048）`，下限 1024。公式保证「预算内的结果 + 固定开销 + 压缩到保留区内的历史」装得下可用输入；下限防止极小窗口把预算压到 0 后模型完全读不到任何块。
- 单块内容超过整个预算时（多为窗口配置不足），任务以 `no_progress` / 轮次上限收敛到 `needs_attention`，跳过提示中说明需要调大窗口或调小块大小。

### 2. 紧急截断（最后防线）

- 常规压缩救不回来时（无可压缩历史，或压缩后仍超窗），对历史中较早的**成功**工具结果正文按「头尾保留 + 中段省略标注」截短；从最旧到最新，一轮不达标按半深迭代收紧单条上限（最低 64 tokens）。错误结果与消息结构（工具调用与结果的配对）不动。
- 截断后的投影写回压缩缓存，后续轮次复用；截断标注提示模型「如需完整内容请重新读取」。被截断的结构化 JSON 不再可解析，模型（与幂等脚本）应重新读取——这是有损的最后防线，优先级低于预算拦截与正常压缩。

### 3. 任务级续跑循环

- 服务层的 `drive()` 从「单次运行」改为续跑循环：一轮运行**正常结束**但完成校验未通过、且未被取消 / 暂停 / 等待确认时，带着该轮带回的压缩后历史投影（`RunOutcome::history`）与按 manifest 重建的最新检查点提示重新拉起运行。
- 连续无进展（产物计数无增长，按磁盘上的草稿 / 审查 / 冻结 / 发布产物衡量）达到 3 次续跑才转 `needs_attention`（incomplete）；任何产物增长都重置计数。任务级推进不再受单轮 `max_turns` 限制；总量仍受调用预算与模型尝试上限约束。
- 运行失败（`Err`）不续跑，按既有恢复分类处理；进度快照直接数产物而非 manifest 计数，避免计数更新时机影响判断。

### 4. 资源文档与角色边界

- 协调者角色与 `smart-translator` 技能补充「单轮并行 `read_chunk` 不超过 2 个、收到预算跳过提示后分批读取」的指引。指引只用于降低无效轮次，不是防线。

## 后果

- 窗口内不再可能被一轮并行工具调用击穿；`input_too_large` 只在「单块内容本身超过整个可用输入」时出现，且错误语义明确指向配置问题。
- 模型中途输出文本不再终结任务；长任务跨多次运行推进，日志与事件按 `run_continue` / `continuation_stopped` 区分。
- 续跑提示复用主提示（按 manifest 重建），任务从磁盘检查点继续，不重复已完成的工作；每次续跑的用量、压缩与工具轨迹都独立记入会话 journal。
- e2e 覆盖：批量读块被预算节流后任务仍完成（跳过提示回传模型）；模型提前收工后自动续跑到完成。压缩有损性的边界（截断破坏 JSON 结构后由幂等工具重读自愈）由同一用例覆盖。
