# ADR 0024：翻译设定集冲突保留既有值，不中断整页

- 日期：2026-10-04
- 状态：已接受

## 背景

ADR 0017 定下「既有译名和文风不可改写，冲突拒绝」，实现里把「拒绝」落成了**整页失败**：
`merge_bible` 一旦发现模型对同一专名给出不同译名，就报「模型改写了锁定译名，请重试本页
翻译」；同一别名被两个词条认领时同样报错中断。

用户实测（小说收藏首篇，opencode 网关 + `deepseek-v4.1-flash`，`reasoning_effort: low`）在
第 1 页就撞上这条错误。复现确认两条路径都会中断整页：

1. **页内自冲突**：第 1 页尚无任何锁定条目，模型自己在同一次响应里对同一 source（或一个
   source 命中另一条的别名）给出两种译名——此时根本没有「锁定译名」被改写，报错文案也不
   属实。
2. **跨页重提议**：锁定设定已落盘，后续页模型把同一个名字换成另一种写法。

中断是死路：设定集只增不改、重译（force）也沿用同一份锁定设定，因此「重试本页翻译」在
持久冲突下**永远失败**，且模型每次要重跑两轮请求（费用）。同一 ADR 里文风冲突的处理是
保留既有 `style` 静默合并，专名却整页失败，二者不自洽。

## 决策

- 专名冲突与文风冲突统一为**保留既有值**：模型提出不同译名时沿用既有译名，该词条的别名
  与说明仍照常合并；不报错、不中断整页，也不改写锁定译名。
- 同一名字（source 或别名）被两个词条认领时，**先到者保留，后到者丢掉该重复别名**，词条
  本身仍进入设定集；不再报「别名指代冲突」。
- 页 1 无锁定设定时，模型自己的重复条目按同一规则取先到者。
- 仍然只增不改：任何路径都不会覆盖已落盘的 source→translation 映射。真正的漂移风险
  （改写锁定译名）依然被挡住，被丢弃的只是模型的改写提议。
- 上架条件不变：不改 IPC、不改 `settings.json`、不改缓存文件格式与目录布局。

## 影响

用户不再因为模型语义不一致而卡住整页；代价是模型提出的「更好译名」会被静默忽略——首选
译名来自首次出现的页，保持全篇一致。设定集冲突不再有用户可见错误，界面只保留翻译中 /
已译 / 失败三态，失败仅剩网络、结构、行对齐与超限等真错误。

离线验收改为：页内自冲突取先到者、跨页改写被丢弃且页译文照常产出、重复别名归先到者、
Pass 2 仍带锁定译名（`translation::tests::locks_existing_names_against_model_rewrites`、
`two_pass_http_preserves_shared_bible_and_page_scope`）。若日后需要用户可干预译名（编辑
设定集 / 手动清除锁定设定），需新开 ADR。
