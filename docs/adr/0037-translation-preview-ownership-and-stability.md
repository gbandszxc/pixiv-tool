# ADR 0037：翻译预览的归属、尾窗与稳定展示

- 状态：已接受（细化 [ADR 0030](0030-translation-stream-preview-and-usage.md) 的流式预览，
  适配 [ADR 0035](0035-whole-novel-agent-translation.md) 的整篇 Job）
- 日期：2026-10-25
- 关联 ADR：[ADR 0030](0030-translation-stream-preview-and-usage.md)、
  [ADR 0035](0035-whole-novel-agent-translation.md)、
  [ADR 0036](0036-translation-runtime-guard-and-continuation.md)
- 规格：[SPEC](../SPEC.md) §3.2 / §4.3 / §7.1，[DESIGN](../DESIGN.md) 小说翻译状态页

## 背景

整篇 Job 化后，主会话与翻译 / 审查子任务各自是独立的运行层 `RunState`，但预览仍只有
`JobEvent.preview` 一个槽位。实测界面出现三类问题：

1. **内容混着、跳来跳去**。默认单小说子任务并发 4，四路翻译 / 审查子任务与主会话
   同时把正文和思考写进同一个槽位，界面以 150ms 级频率在几块之间切换；切换发生时
   也没有任何归属提示，用户无法判断这句话是主会话还是某个子任务。
2. **预览不连续、像卡住**。`RunState.preview` 只追加不清空，同一次运行的多个模型轮次
   拼成一个字符串；前端又取**开头** 60 字符（ADR 0030 的意图是思考尾窗），字符串越长，
   画面越停在最早的那句话上。思考一旦出现还会长期压住正文（直到 32KB 才清）。
3. **运行层污染 Job 状态**。子任务的预览事件带着自己的 `phase`（翻译 translate /
   审查 review），事件合并器把阶段变化当成立即事件，前端整包覆盖快照后，头部阶段
   文案会跟着最后流式的角色跳；子任务终态还会把 `error_code` 带进 Job 快照。
   另外 `novel_translation_status` 的 `preview` 一直取内存里从未更新的默认值，
   重新可见 / 手动刷新会把预览行清空。

## 决策

### 1. 预览带归属

`Preview` 增加 `owner: CurrentWork`（`role` + 可选 `page` / `chunk_id`）。主会话不标块；
翻译 / 审查子任务在派发时填入本块页码与块 ID（`run_translator` / `run_reviewer` 通过
`RunRequest::with_current_work` 传入）。前端在预览行前显示「翻译 c0003」/「审查 c0005」
（主会话不加前缀），`title` 同步带前缀。

### 2. 尾窗取代累积

- 运行层每个角色的预览只保留最近 240 字符（char 边界），不再无限累积；完成态的
  最终回答同样取尾部。
- 每次模型调用开始与每次工具派发时清空该角色的预览，并发一条空预览事件作为
  「本轮生成结束」占位。空占位是让出槽位的信号，不是错误。
- 前端取尾部 60 字符展示（超出加前导省略号）；思考与正文仍共用一行，正文优先。

### 3. 运行层只做预览，不推进 Job 状态

`JobProgressSink` 把主会话与子任务的运行层事件统一归一化为 `message = "preview"`：
非 Running 的终态改写为 Running 并清空文本（保留归属，用于释放槽位），
`run_start` 等杂项同样作为空占位；`error_code` 不从运行层透出。Job 的阶段、状态、
错误只由 `TranslationService` 的状态机通过进度 / 状态事件推进，事件合并器也只从
非预览事件更新 `job_phase`。子任务预览事件不得改写 Job 阶段。

### 4. 稳定选择展示对象

`JobEmitter` 维护主会话与并发子任务的分槽预览：

- 主会话正在生成（最近一次非空预览，未被空占位清除）时，展示主会话；
- 否则展示当前焦点子任务块；焦点块生成结束前，其他子任务的更新不抢占；
- 焦点块结束或超过 5s 没有更新时，让给最近仍在输出的块；
- 所有角色都刚结束一轮时保留上一段文本（不把预览行清空），直到新的生成接管。

选择结果会盖到**每一条**下发事件上，进度 / 阶段事件不会再把预览行打回空白。
`novel_translation_status` 的 `preview` 与 `current` 取事件合并器最后一次下发的值，
刷新后与界面一致。

## 影响

- 预览行从「最后一条事件」变成「当前主导生成者」：并发子任务之间不再逐帧抢同一行，
  主会话恢复输出时立即夺回；子任务结束会主动让位。
- 阶段文案、计数与错误只受 Job 状态机影响，不再随子任务事件抖动。
- 预览内存有上界（每角色 240 字符）；正文与思考仍不落盘、不写日志。
- 局限：主会话的正文仍是模型叙述（如「我先读取原文块与译文」），不是任务摘要；
  这是「预览反映最新生成」的既定取舍（ADR 0030），不做语义改写。

## 验收

- 单元测试覆盖：主会话优先与空占位让位、并发子任务焦点粘滞、子任务阶段不改写
  Job 阶段、尾窗不切断字符。
- 浏览器验收覆盖：预览行显示子任务归属、长文本只展示尾部 60 字符、思考期与正文的
  切换。
- 真实任务复测：翻译 / 审查阶段并发运行时，预览行不再高频跳块；暂停 / 完成 /
  失败后刷新快照，预览与当前页块保持。
