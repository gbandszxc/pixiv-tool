## 背景

真实任务 `29406946`（6 块）在 256 次调用预算内三次停下，最终 `budget_exhausted`：

1. 冻结风格写着“保留颜文字与拟声词”，术语表 29 条锁定译名本身是片假名原文；
   同时翻译 / 审查提示词要求“拟声词必须译成目标语言、不得残留片假名专名”。
   翻译子 Agent 按冻结约束保留假名，审查子 Agent 按纯净度规则判 `major`，
   同一块在“修订 → 复审”之间永远不收敛。
2. 写入校验按整块假名占比 15% 放行，审查规则却是残留即问题。草稿能落盘但必然
   被判 `needs_fix`，两个门禁对同一份译文给出相反结论。
3. 审查模型把冻结术语本身判成残留（`バニーメイド` / `ハイグレ` 明明按表锁定），
   进一步放大返工量。
4. 每块返工额度用尽后用户手动 `resume` 会清空按块计数（ADR 0038 设计），
   于是“继续”一次就重开一轮返工；累计预算成为唯一刹车。
5. 工具失败日志只记 `status=error`，31 次 `submit_translation` 校验失败无法从日志
   定位原因。

结论：提示词、约束生成、写入校验、审查判定必须共用同一套语言口径；否则任何
“保留还是翻译”的歧义都会转成预算消耗，而不是可收敛的失败。

## 决策

### 1. 统一三点语言策略

日译目标（目标语言不是日语）统一按以下三条执行，扫描、翻译、审查、校验同源：

1. **拟声词必须翻译**：平假名 / 片假名拟声拟态词译成目标语言的声音、动作、
   触感或状态描写，不保留假名原文。
2. **专有名词用目标语言或英语**：片假名专名、舶来语与作品内自造词优先译成
   目标语言；没有合适译名时允许官方英文名或通行罗马字拼写；不保留片假名原文。
   锁定译名同样受此约束。
3. **颜文字原样保留**：`♡`、`♥`、`♪`、`w` / `ww`、场景分隔符 `◆`、括号符号
   组合等非自然语言符号组合不翻译、不改写、不删除。

拟声词是语言内容，必须翻译；颜文字是符号组合，必须保留。扫描提示词不得再把
“保留拟声词 / 假名”写进风格。

### 2. 写入校验与审查同口径

- 日译目标的提交校验（`submit_translation` / `revise_draft` / 合并 / 发布）改为
  逐片段假名零容忍：命中即 `japanese_residue`（`major`），错误详情只给片段 ID
  与规则，不含正文。
- 豁免：颜文字标点（`・`、`･`、`ﾉ`、`ﾟ`、`ﾞ`）、ruby 标记整体、URL、inline code，
  以及旧任务中已冻结的假名锁定术语（`validate_draft_with_policy` 的
  `exempt_terms`）。新约束不允许再产生假名锁定术语，豁免只为历史任务可用。
- 审查提示词与上述口径一致：残留假名拟声词 / 片假名专名至少 `major`；颜文字
  原样保留不记问题；英文、罗马字或目标语言的锁定术语均合规。

### 3. 冻结前冲突检测

`submit_scan` 与 `freeze_constraints` 在日译目标下校验：

- `locked_translation` 含假名（颜文字标点除外）→ `constraint_policy_conflict`；
- 风格文本出现“保留拟声 / 保留假名 / 保留日文拟声”类表述 → 同类拒绝；
- 风格允许“原样保留颜文字”，不视为冲突。

拒绝发生在写盘前，错误返回具体术语或字段；协调者修正对应块的扫描后重新冻结。
运行层仍以工具纠正次数与轮次上限兜底，不引入新的无限循环。

### 4. 工具失败日志补错误码

`tool_end` 在 `status=error` 时附带结构化 `code`（从工具结果的 `error.code`
提取），不记录正文参数。`submit_translation` 的校验失败因此可按错误码统计。

## 后果

- 提示词、约束生成与两个门禁对“什么必须翻译、什么必须保留”只有一个答案，
  不再产生“满足约束就被校验拒绝、满足校验就被审查拒绝”的死锁。
- 假名残留从“比例放行”变为确定性拒绝；模型必须显式处理，失败更早、更可诊断。
- 新规则使内置提示词资源 hash 变化：按既有资源版本校验，旧 Job 不能静默续跑，
  需要重新发起翻译（旧任务产物仍保留，仅不可 resume）。
- 残留风险：零容忍会提高弱模型的单次提交失败率，依赖有限的工具纠正与按块返工
  额度收敛；颜文字白名单是字符级的，极端排版下可能把个别装饰性假名当颜文字放过。
