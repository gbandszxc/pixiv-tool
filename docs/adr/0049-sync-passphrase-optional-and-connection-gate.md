# ADR 0049：同步口令可选与测试连接门控云端备份回显

- 状态：已接受（改写 [ADR 0048](0048-webdav-sync-history-and-auth.md) 决策 3 的口令长度
  强制与决策 4 的 `sync_test_connection` 语义；包格式与凭据落点不变）
- 日期：2026-11-04
- 关联 ADR：[ADR 0044](0044-structured-command-error-payload.md)（结构化错误载荷）、
  [ADR 0048](0048-webdav-sync-history-and-auth.md)（WebDAV 同步基座）
- 规格：[SPEC](../SPEC.md) §5.2 / §6.1 / §7 / §10 / §11

## 背景

ADR 0048 把同步口令定为 8~256 字符的必填凭据：上传 / 恢复前必须先想好并记住一个
口令。对单人本地工具这是偏高的使用门槛——多数场景下用户只想把历史与登录态搬到另一台
设备，并不评估「托管方能看到密文」之外的威胁模型；强制口令带来的结果往往是用户
随手设一个弱口令，安全收益趋近于零，而「忘记口令 = 云端备份永久不可解密」的风险
反而真实存在。

同时，`sync_test_connection` 只回答「连通与否」：用户无法在动手前知道云端是否已有
备份、备份是什么时候的，上传 / 恢复按钮也与连接状态无关，误操作成本高。

## 决策

### 1. 同步口令可选、无长度限制、内置默认口令

- 口令**不再有长度限制**：删除 8~256 字符校验与 `sync_passphrase_invalid` /
  `sync_passphrase_missing` 两个错误码（含前端 i18n 键）。口令解析仍整体 trim，
  trim 后为空 = 未设置。
- 未设置口令时，上传与恢复统一使用**内置默认口令**
  （`keys::DEFAULT_PASSPHRASE`，形如 `pixiv-tool:default-sync-passphrase:v1`）
  派生加密密钥。包格式（`PTSYNC01` + PBKDF2-HMAC-SHA256 600k + AES-256-GCM）、
  salt / nonce 语义、AAD 绑定全部不变——默认口令只是 PBKDF2 的输入，因此**用默认
  口令上传的包在任何设备上都能直接恢复**（无需迁移）。
- `settings_save` 的 `sync_passphrase` 参数语义不变：省略 = 保持，空串 = 删除条目。
  WebDAV 密码的语义与校验不变（用户名非空时仍必须有密码，ADR 0048 决策 1）。
- **保护强度向用户明示为混淆级**：默认口令编译进二进制，可防 WebDAV 托管方与偶然
  拿到文件者直接读明文，不对抗能提取常量的攻击者。口令字段的帮助文案三语同步写明
  「留空用内置密钥加密（保护较弱），建议设置自定义密码，丢失后无法解密云端备份」，
  风险登记见 SPEC §11 R15。

### 2. 测试连接回显云端备份

- `sync_test_connection` 在 MKCOL 成功后追加**备份探测**：对远端固定文件发
  `HEAD`（2xx 取 `Last-Modified`，404 = 无备份；极少数不支持 HEAD 的 405/501 回退
  `GET` 只取响应头，不读 body）；认证失败与其他 HTTP 错误原样上抛，网络层错误沿用
  「跟随系统代理失败 → 直连重试一次」模式。返回体从
  `{status, http_status}` 扩为 `{status, http_status, has_backup, backup_time}`，
  `backup_time` 是远端 `Last-Modified` 原文（HTTP 日期，前端用 `Date` 解析）。
- 探测只读元数据，不下载、不解密包内容；同步口令仍与测试无关（可以先测连通再设口令）。

### 3. 界面：测试门控与备份回显卡

- 上传 / 从云端恢复在**本次会话测试连接成功前禁用**；未测试时按钮行下方显示 12px
  提示行说明先行动作。测试连接为 md-filled-button 主动作，上传 / 恢复为
  md-outlined-button 次要动作（按钮词汇表不变，见 `DESIGN.md`）。
- 测试成功后提示行替换为**云端备份回显卡**（surface-container-low 底、outline 25%
  描边、`--radius-control` 圆角；lucide cloud-check（primary）/ cloud（muted）图标）：
  「已有备份 · <时间>」或「暂无备份 · 上传后在此目录创建同步文件」。上传成功即把
  回显刷新为最新备份（本机完成时刻）。
- 回显是会话级状态（SettingsPanel 持有）：切到高级索引页再回来保留，关闭设置复位；
  保存 / 取消整表重置。地址、用户名或 WebDAV 密码草稿一旦变化，测试结果即失效
  （需重测）——同步口令草稿不影响连通性，不触发失效。

## 后果

- 首次使用成本从「先设计并记住一个口令」降为「填地址就能测、测完就能传」；默认
  路径下云端备份对拥有应用二进制者不再保密，这是明确的、已向用户披露的取舍。
- 口令从必填变可选后，「忘记口令」的风险只存在于设置了自定义口令的用户；帮助文案
  与恢复失败文案（`sync_decrypt_failed`）保留明确提示。
- `sync_test_connection` 从「只 MKCOL」变为「MKCOL + HEAD/GET 探测」，第三方服务对
  HEAD 的支持成为新的兼容面（405/501 已有 GET 回退，其余状态码按既有错误语义上抛）；
  真实服务端（Nextcloud / 坚果云等）补测时需覆盖探测路径。
- 前端动作可用性依赖测试结果，意味着改地址 / 用户名 / 密码后必须重测一次才能上传 /
  恢复——这是有意设计的防误操作闸，不是缺陷。

## 替代方案

- **保留必填口令**：安全上最保守，但把门槛压在最高频路径（换设备搬数据）上，
  用户会为省事选弱口令，实际安全性不升反降，放弃。
- **默认口令 + 可选服务端加密（双层）**：需要用户理解两层密钥的关系，与「把复杂性
  留在内部」冲突；单层「自定义口令 or 内置口令」已覆盖需求。
- **用 PROPFIND 取备份时间**：WebDAV 标准做法，但要解析 XML 多媒体簿响应且部分
  服务禁用 PROPFIND；HEAD/GET 的 `Last-Modified` 已满足「有没有、什么时候」两个问题。
- **测试后长期记忆备份状态**：需要持久化 + 过期策略 + 多目录歧义；会话级回显已够用，
  每次打开设置重测一次的成本可接受。
