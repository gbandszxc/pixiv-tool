# ADR 0035：整篇小说 Agent 翻译（Job 化）

## 背景

[ADR 0017](0017-novel-page-translation.md) 以「单个 Pixiv 阅读页、准备与翻译两轮请求」为单位，并在 `data/translations/<novel_id>/<hash>.json` 中保存共享设定集与页译文。该模型在短页上工作良好，但对整篇作品存在结构性限制：

- 单页请求无法基于全篇做术语、人物关系与风格准备；后出现的角色与设定不能反向影响前文。
- 单页 120KB、正文 8MB 的输入上限不是按模型能力切块，长页与长输出容易触顶或被截断。
- 准备与翻译只有固定两轮，没有独立审查、整体复核与局部返工；模型声明完成不等于产物合格。
- 前端持有长 invoke、队列与跨页状态；离开页面后的失败、暂停和恢复边界不清晰。
- 缓存按页文件组织，没有「一次任务拥有全部中间产物」的模型，清理与恢复容易留下孤儿。

项目已引入通用 Agent 运行层（[ADR 0034](0034-rig-agent-kernel-and-rust-toolchain.md)），并具备原生工具调用、子 Agent、预算、压缩、恢复与检查点能力。整篇翻译应以一个完整 Job 为单位重建流程，而不是继续扩展单页两轮。

## 决策

### 1. 翻译单位：一篇作品一个 Job

- Job 的单位是一篇 Pixiv 小说作品的全部阅读页；系列中的其他作品各自独立创建 Job，不合并、不共享术语。
- Job 的输入身份由「作品 + 原文版本 + 目标语言」确定；内置资源版本与配置快照随 Job 记录，用于恢复校验与审计。同一作品、同一原文版本、同一目标语言的重复启动加入既有 Job；显式重译创建新 Job，旧结果保留到新结果通过为止。
- 原文已是目标语言且未强制翻译时，不创建 Job，直接返回「无需翻译」；强制翻译仍走完整流程。
- Job 状态与阶段分离：状态包含排队、运行、等待确认、暂停中、已暂停、需要处理、取消中、已取消、已中断、已完成、已删除；阶段为原文准备、约束准备、翻译、审查、返工、整体复核、发布。

### 2. Pass 0～3 + 整体复核 + 局部返工

主 Agent 负责阶段推进与门禁判断，Rust 工具执行确定性操作并校验提交条件：

1. **Pass 0（原文准备）**：注册整篇原文，建立页 / 行 / 片段映射；按语义边界和字符预算切块，生成前后邻接参考窗口；记录原文 hash。
2. **Pass 1（约束准备）**：逐块扫描术语、人物关系、风格与对白；全部块扫描有效后才允许冻结。聚合时既有锁定译名与用户确认值优先，冲突显式记录；冻结后写入约束版本与检查点。
3. **确认分支**：默认自动按推荐术语与风格继续；启用「翻译前确认」时，主 Agent 在冻结约束后进入等待确认，用户在浮层内修改术语与风格并确认后继续。
4. **Pass 2（翻译）**：按块派发独立翻译子 Agent；子 Agent 只翻译主块，邻接上下文仅用于理解、不进入输出；完整响应经结构与覆盖率校验后提交草稿。
5. **Pass 3（审查）**：按块派发独立审查子 Agent，对照原文、译文与冻结约束，检查漏翻、错翻、术语、风格、语气、目标语言与标记保真；不通过时定向修复或重译受影响块，再由审查子 Agent 复检。
6. **整体复核**：主 Agent 读取块摘要、审查汇总与抽样结果，形成全局复核记录；不把整篇原文或整篇译文重新塞回主上下文。
7. **发布**：块覆盖、审查结论、整体复核与合并校验全部满足后才写入正式结果；仍有问题则标记部分完成或需要处理，不能冒充通过。

模型声明完成不构成完成条件。完成由 Rust 工具按实际产物与审查状态校验。

### 3. 页 / 行 / 片段映射与校验

- 页码从 1 起，行号为页内 0 起，与阅读器页 / 行契约一致；片段 ID 固定为 `p<页三位>-l<行三位>-s<序号>`（如 `p003-l012-s0`），由原文解析层生成，模型不得自造。
- 片段类型包括可译文本、章节标记、注音标记与纯标记行；超长单行在句末标点或空白处拆成多个片段，切点不落入 `[...]` / `[rb:...]` 标记内部。
- 校验以片段为单位：覆盖（缺失 / 多余）、顺序、重复、空值、目标语言、标记保真（章节、ruby、图片 / 跳转标记数量与位置）以及结构化 schema。
- 合并阶段再做跨块校验：同一片段只能出现一次，页 / 行映射必须可还原，标记问题汇总为可定位的问题列表。
- Markdown 合并稿是发布后的派生产物；阅读器以正式结果投影（页 → 行译文）为准，不以 Markdown 反向解析。合并稿缺失译文时回退原文，但不代表该页已通过审查。
- 覆盖、顺序、重复或标记校验失败时不得发布；局部返工只重译受影响块，已通过块与旧可读版本不被失败结果覆盖。

### 4. 子 Agent：一层、独立上下文、工具白名单

- 子 Agent 默认一层：主 Agent 可以派发翻译 / 审查子 Agent，翻译与审查子 Agent 不再派生下一层。
- 每次派发使用独立会话与独立上下文，显式传递块内容、前后文、约束版本、目标语言、输出归属与角色定义；不复制完整父会话。
- 子 Agent 回传父会话的只有状态、摘要、产物引用与用量；完整产物写入 Job 目录。
- 工具按角色白名单注册，未注册工具、路径参数、通配符与跨角色工具一律拒绝：

| 角色 | 工具职责 |
|---|---|
| 主 Agent | 加载内置资源、准备原文、读取块摘要 / 块内容、提交扫描、冻结约束、派发翻译 / 审查、读取审查摘要、合并草稿、记录整体复核、发布、按依赖重置阶段、查询任务状态 |
| 翻译子 Agent | 加载资源、读取指定块、提交该块译文 |
| 审查子 Agent | 加载资源、读取指定块、读取该块译文、提交该块审查结论 |

- 主 Agent 不持有整篇原文或整篇译文；准备阶段只返回页 / 块 / 片段计数与预算，复核阶段只读取摘要、抽样与问题列表。
- 工具结果设长度 / token 上限；超出时由调用方分页或改传产物引用，不用静默截断掩盖缺失。

### 5. 并发、预算、恢复与完成判定

- 模型请求受三级闸门控制：全局并发、单小说并发、同时活跃小说数；实际并发取全局与单小说的较小值，一本长篇不能占满全部槽位。派发另受单小说派发闸门限制。
- 等待子任务、执行工具与暂停期间不持有模型请求许可；压缩摘要请求同样经过全局闸门。
- 整篇维护累计模型尝试预算；未显式配置时按 `64 + 32 × 初始分块数` 自动计算（数值于 2026-10-25 上调，见 SPEC §4.3）。父任务、子任务、摘要、传输重试与返工共享该预算；手动恢复、再次派生或细分不重置预算。
- 压缩在完整工具批次之间执行；摘要失败保留原记录并暂停，不无限压缩。压缩后的投影只影响后续请求，正式产物仍从 Job 文件读取。
- 恢复分类：明确未发送的连接失败可有限重试；限流与暂时性服务错误按退避重试并尊重服务建议；鉴权、余额、模型不存在与配置不兼容直接暂停；已发送但结果未知默认不自动重放；输入超限先压缩或细分；输出截断缩块重做；工具参数错误有限纠正；质检问题只返工受影响块。
- 暂停表示停止派发并停在最近检查点；取消立即传播取消信号并保留已提交产物；两者都不清预算与重试记录。
- 应用重启只把排队、运行、暂停中、取消中的 Job 改为「已中断」，不自动发起付费请求；用户恢复时校验缓存世代与资源版本，不一致则拒绝静默续跑。
- 完成判据由 Rust 校验：全部块草稿通过结构校验、审查结论与草稿版本匹配且通过、整体复核通过、合并报告通过、正式结果状态为完成。

### 6. 持久化：Job 拥有者与清理生命周期

每个 Job 独占一个目录：

```text
data/translations/v2/<novel_id>/<job_id>/
  manifest.json           # 身份、状态、阶段、输入 hash、资源版本、计数、用量、预算
  settings_snapshot.json  # 不含凭据
  resources.json          # 资源 ID / 版本 hash
  source/                 # 原文映射与输入快照
  preparation/            # 扫描结果、冻结约束
  chunks/                 # 源块与译文草稿
  reviews/                # 单块审查与合并报告
  output/                 # 正式阅读器结果、整体复核、合并稿
  sessions/               # Job 内会话产物（预留，禁止落到全局目录）
  checkpoints/            # 阶段检查点
  temporary/              # 原子写入临时文件
```

- 原文、译文、术语、审查、整体复核、检查点、会话与临时文件全部落在所属 Job 内；Rig 或运行层不得在 config、用户主目录或其他 Agent 数据根留下副本。
- 所有产物写入使用「临时文件 + rename」的原子提交；流式内容不直接写正式路径。
- 全部产物使用带 `schema` 与 `kind` 的 JSON 信封；Job manifest 记录输入 hash、约束版本与 schema 版本，草稿 / 审查带各自版本并拒绝版本回退。恢复时校验版本，不把旧产物冒充为新结果。
- 缓存清理仍由既有 `clear_cache("translation")` 入口负责：它递归清除 `data/translations`，同时覆盖 v1 旧缓存与 v2 全部 Job（含 source / chunks / reviews / checkpoints / sessions / temporary / output），不只删除最终译文。
- 运行中或收尾期间拒绝清理；暂停且已到检查点、等待确认、失败与已中断的 Job 可以释放使用许可，但清理会同时删除其恢复数据。
- 清理成功后递增缓存世代；迟到回调携带旧世代时写入层直接拒绝，且不重建已删除的 Job 目录。删除 Job 先写 `.deleting` 标记，失败保留标记；启动恢复时收尾未完成的删除。
- 单个 Job 的正式结果与中间数据不跨 Job 共享文件或引用，避免删除一个 Job 破坏另一个 Job。
- v1 缓存保持只读兼容：`src-tauri/src/translation_legacy.rs` 保留旧单页实现，`novel_translation_get` 仍可读取旧记录；投影统一标记为部分完成，绝不冒充新流程已审查结果，也不被 v2 Job 引用。

### 7. 事件、状态与前端契约

- 后端是运行状态真相源：启动命令快速返回 Job 快照，后台 tokio 任务继续执行；Job 状态、确认、暂停、恢复、取消、删除与预览命令的最终清单见 SPEC §7。
- 进度传输从单命令的 Channel 事件流改为后端 Job 事件 `translation://job`：事件携带 Job / 小说 / 阶段 / 计数 / 用量 / 当前工作 / 预览 / 安全错误码，并对每个 Job 单调分配 `seq`。
- 前端挂载采用「快照 + 序号追赶」：先取快照，再订阅事件，按 `seq` 丢弃重复或迟到事件，避免「先读快照再订阅」丢事件。高频进度在传输层合并节流；阶段切换、终态与错误立即发送。
- 浮层只显示当前小说；底部状态栏复用多小说任务选择入口。关闭浮层不取消任务，离开小说页不中断后台 Job。
- 与既有决策的关系：
  - [ADR 0029](0029-translation-progress-events.md)：保留「后端续跑、离开页面不中断、失败可回显」的目标，但事件载体由 `novel_translate_page` 的 Channel 改为 `translation://job`，运行状态由后端 Job 持有。
  - [ADR 0030](0030-translation-stream-preview-and-usage.md)：保留流式预览、思考尾窗与 token 用量展示；字段由 Job 事件的预览 / 用量承载。
  - [ADR 0031](0031-parallel-novel-translation-and-status-bar-picker.md)：保留多小说并行与底栏任务选择；并发控制升级为全局 / 单小说 / 活跃小说三级调度，同一小说仍串行。
  - [ADR 0033](0033-translation-dynamic-output-cap-and-default-thinking.md)：保留按输入分档的输出上限与默认思考；参数经 provider 归一化后进入每次模型请求。
  - [ADR 0025](0025-translation-streaming.md)：生成请求继续使用流式传输；思考与正文增量分类、用量解析沿用既有协议语义。

### 8. 设置分层

- 一级只保留连接与常用项：接口协议、API URL、API Key、模型、目标语言、启动前确认开关、连接检测与「高级设置」入口。
- 二级高级设置按分类组织运行参数：模型能力与上下文、并发与任务预算、重试与质检、分块与前后文、请求扩展 JSON、诊断。一级只显示「推荐 / 已修改项数」摘要，不铺开参数表。
- 运行参数参与保存前交叉校验（分块目标 ≤ 上限、输出上限 ≤ 上下文窗口、近期历史 + 摘要 ≤ 上下文窗口等）；越界值拒绝保存并在二级分类内定位。
- 诊断开关只影响本次运行 / 本次设置会话，不写入 `settings.json`；日志不得记录原文、译文、提示词、凭据或完整请求头。

### 9. 明确不包含

- MCP、自由聊天页面、外部插件、任意 shell、系列批量翻译、跨作品共享术语。
- 通用翻译服务或其他业务的 Agent 页面；本 ADR 只覆盖小说阅读器发起的整篇翻译 Job。

## 备选方案

- **继续 ADR 0017 的单页两轮并逐步打补丁**：无法解决全篇术语一致性、长输入长输出、独立审查与任务级恢复；每页独立请求还会放大重复计费。未采用。
- **主 Agent 持有全文并在单会话内完成全部翻译**：上下文不可控，长篇小说必然触发压缩与截断，且审查与翻译不独立。未采用。
- **以 Markdown 合并稿作为阅读器真相源**：会丢失页 / 行 / 片段映射与审查状态，无法稳定支持双语对照与局部返工。未采用。
- **把会话、摘要或检查点放到全局 Agent 目录**：清理、恢复与防复活无法按 Job 收敛，容易产生孤儿或跨任务污染。未采用。
- **固定两轮、不设预算与压缩**：长请求与长输出下无法恢复；预算与压缩是防止失控和无限重试的必要边界。未采用。
- **引入 MCP / 通用聊天 / 第三方编排框架的调度**：超出产品边界，且会把权限、存储与状态真相源移出 Job。未采用。
- **自研协议层替代 Rig**：见 [ADR 0034](0034-rig-agent-kernel-and-rust-toolchain.md)，重复实现且难以维持三协议一致。未采用。

## 后果

- **模型调用量上升**：整篇需要扫描、翻译、审查、整体复核与可能的返工，调用次数明显高于单页两轮；由累计调用预算、并发闸门与暂停 / 取消控制成本。推荐参数需用真实长篇校准，不能把计划值当成已调优结果。
- **清理语义更重**：`clear_cache("translation")` 会同时删除 v1 缓存与 v2 的原文、译文、会话、检查点与恢复数据；清理后暂停 / 确认中的 Job 不可恢复。界面与文档必须明确这一后果。
- **恢复依赖 Job 完整性**：手工删除文件、manifest 损坏或资源版本变化会导致 Job 不可恢复或标记缓存损坏；系统按拥有者整体清理，不根据旧摘要盲目重建。
- **前端契约迁移**：原先依赖单命令 Channel 的前端逻辑需要改为 Job 快照 + `translation://job` 事件；旧事件流不再作为新流程的真相源。
- **旧缓存只读**：v1 记录仍可阅读，但不会自动升级为 v2 已审查结果；用户重译会创建新 Job。
- **可观测性增强**：事件、日志与 manifest 提供阶段、计数、预算、压缩、重试、恢复与终态定位；日志仍遵守脱敏与不记录正文的边界。
- **验收重点**：页 / 行 / 片段映射、覆盖与顺序、标记保真、审查独立性、局部返工、预算与压缩、暂停 / 取消 / 恢复、清理世代、v1 只读兼容与 `translation://job` 事件追赶。
