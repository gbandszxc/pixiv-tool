# ADR 0052：竖屏最大化布局适配

- 状态：已接受（推翻 [DESIGN.md](../../DESIGN.md) §Layout 旧决策「侧栏不会因媒体查询自动隐藏，仅由用户手动折叠」；属用户可见产物布局变化）
- 日期：2026-11-08
- 关联 ADR：[ADR 0012](0012-browse-mode-own-ui.md)（浏览模式与作品查看器 / 小说阅读器）、[ADR 0015](0015-navigation-download-workspace.md)（核心导航与非模态下载工作区）、[ADR 0039](0039-ugoira-playback-and-page-download.md)（查看器与多 P 按页下载）、[ADR 0045](0045-download-grid-view-and-local-image-protocol.md)（下载历史宫格）
- 规格：[SPEC](../SPEC.md) §6.1 / §6.4；视觉规则同步维护于 `DESIGN.md` §Layout / §Do's and Don'ts / 浏览模式组件 / 核心导航与下载工作区，以及 `.impeccable/design.json`

## 背景

桌面双屏一横一竖，竖屏作漫画 / 小说消费端。参考尺寸：Windows 27" 1440×2560 @125% → 逻辑 **1152×2048**；Mac 1152×2048 HiDPI 按逻辑点理解。横屏基准 **1200×800**。竖屏是「中等宽 + 超高」的视口，既不是极窄窗口，也不是物理旋转设备；现行布局（侧栏常驻、详情页左右分栏右 320px 信息列、表格 `min-width 760px`）在超高竖屏上把横向空间挤占给侧栏与信息列、纵向却大量空置，阅读与列表消费体验差。目标：仅竖屏最大化时启用专用布局，非最大化窗口沿用横屏布局。

## 决策

### 1. 仅竖屏最大化时生效，不按设备物理方向硬判定

- **判定信号**：窗口最大化 && 逻辑宽高比 < 0.8 && 逻辑高度 ≥ 900；**退出滞回** = 比例 ≥ 0.88 或高度 < 820。监听窗口 resize / move / DPI 变化重算，判定一律基于逻辑尺寸（与 CSS 像素 / 逻辑点一致）。
- **范围**：仅**竖屏最大化**时应用专用布局；**非最大化窗口沿用横屏布局**（基准 1200×800）。不按设备物理方向硬判定，最大化到横屏也不启用。

### 2. 推翻 DESIGN.md:109，侧栏自动折叠为 72px rail

- 仅竖屏最大化时侧栏自动折叠为既有的 **72px rail**（只显示图标；账号底栏折叠态只留头像）。这**推翻** `DESIGN.md` §Layout 旧决策「侧栏不会因媒体查询自动隐藏，用户通过头部行的折叠按钮切换」。
- 折叠态本就存在（侧栏 256px / 折叠 72px、48px 胶囊导航项），复用既有组件；`App.vue` 复用 `captureLayout/restoreLayout` 保滚动锚点。
- 用户的手动折叠 / 展开按钮可**覆盖**自动决策；该覆盖**不持久化**（会话内有效，用户明确不需要跨重启记忆），用户未覆盖时自动决策才生效。非最大化窗口沿用横屏、自动决策不介入。

### 3. 各页面规则目标（中性表述；具体形态由实现自裁，文档不写死数值）

- 详情页：由左右分栏（右 320px 信息列）改为上下堆叠，信息列不再挤占横向空间。
- 小说阅读器：正文限宽居中，避免超宽行长。
- 全屏看图：竖屏默认单页 / 按高度适配 / 关闭双图；会话内用户偏好不被覆盖。
- 历史表格（`min-width 760px`）：竖屏默认宫格；用户显式选择优先。
- 下载面板与翻译浮窗：改为不遮挡内容的可收起形态（具体形态与尺寸由实现决定，不写死）。
- 宫格 `@container` 列数档位沿用不改；触屏保留现有 `@media (hover:none)`，不特意优化。

### 4. 不持久化、不扩面

竖屏布局与用户覆盖均为会话内状态，不写 settings.json、不新增设置项 / schema 键 / i18n 文案 / 路由 / 端点契约。

## 范围与不改动项

- 改：前端布局与样式（`DESIGN.md` / `.impeccable/design.json` / `SPEC.md` §6 同批，本 ADR 记录决策）。
- **不改**：`tauri.conf.json` 的 `minWidth 960`（参考屏逻辑宽 1152 > 960，最大化不溢出）、后端 / Rust、settings schema、i18n、路由、端点契约、`tiered-grid.css`。
- `docs/PACKAGING.md`（未动构建 / 窗口配置）与 `docs/PIXIV-API.md`（未动端点）不改。
- 旧 ADR 不删不改；本 ADR 是推翻既有决策的新增条目。

## 替代方案

- **按设备物理方向（screen.orientation / 物理旋转）硬判定**：不可行。场景是「桌面一横一竖双屏里把竖屏当消费端」，竖屏显示器是固定安装的普通显示器，物理方向不会翻转；窗口可被拖到任意屏，物理方向与当前窗口所在屏脱节。判定应落在窗口实际逻辑几何，而非设备方向。
- **复用 640px 窄屏断点**：不可行。`tauri.conf.json` 的 `minWidth 960` 使视口宽度恒 ≥ 960，640px / 959px 断点基本不触发；且竖屏是「中等宽（1152）+ 超高（2048）」而非「极窄」，窄屏断点的换行 / 纵向堆叠解决不了「超高 + 侧栏与信息列挤占横向」的问题，也不会触发侧栏折叠。故引入独立的「最大化 + 宽高比 + 高度」判定，而非扩展窄屏断点。

## 后果

- 正向：竖屏最大化时横向空间回归内容、纵向被充分利用，漫画 / 小说消费体验改善；横屏与非最大化窗口行为完全不变。
- 代价：新增一套窗口几何判定与各页面的布局分支，需要滞回与锚点保护配合。

## 风险

- **跨屏拖动 / 缩放 / DPI 变化时的布局抖动**：窗口在横竖屏间拖动、最大化 / 还原或 DPI 改变会让宽高比与高度在阈值附近反复跨越，单阈值即时切换会来回抖动。缓解：进入与退出用**滞回**（进入 < 0.8 / 高 ≥ 900，退出 ≥ 0.88 或高 < 820）留出缓冲区；布局切换复用 `captureLayout/restoreLayout` **保滚动锚点**，避免内容跳动与滚动位置丢失。
- 用户手动覆盖与自动决策冲突：以用户最近一次手动操作为准、不持久化；退出竖屏最大化即回到横屏布局。
