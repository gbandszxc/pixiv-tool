# ADR 0018：小说翻译目标语言与语言一致的快速返回

- 日期：2026-10-04
- 状态：已接受

## 背景

ADR 0017 把小说翻译固定为简体中文。用户希望按自己的阅读语言翻译（默认与界面语言一致，可手动指定），并避免把已经是目标语言的原文送进两轮流程空转、白花模型费用。

## 决策

- 设置新增 `translation_target_language`：空串 = 跟随界面语言 `language`；白名单 `zh-CN` / `zh-TW` / `en` / `ja` / `ko` / `es` / `fr` / `de` / `ru`，语言别名（`en-US`、`zh_Hant` 等）归一化后接受，非法值在设置保存与翻译时拒绝。设置页首项为「跟随界面语言（当前语言名）」，其余为白名单语言。
- 两个提示词模板改为 `{target_language}` 占位，运行时注入语言名（如「简体中文」「英文（English）」），并去掉「片假名转中文」等只适用于中文目标的措辞；设定集与译文都按目标语言产出。
- 原文语言在本地按主导文字判定：假名 / 谚文占比 ≥5% 判日 / 韩，汉字为主按简繁用字倾向区分，拉丁与西里尔按主导文字判定（拉丁只匹配 en）。判定不发网络请求，也不落盘。
- 判定结果与目标语言一致时，`novel_translate_page` 直接返回 `status=already_target_language`（不读缓存、不调用模型）；显式重译（`force`）或界面点「仍然翻译」仍执行完整两轮流程，误判可覆盖。
- `novel_translate_page` 返回体由 `[{line,text}]` 改为 `{status,lines,target_language}`，界面据 status 区分「已翻译」与「无需翻译」提示（后者不算成功也不算失败）。

## 影响

新增 1 个设置键（白名单 18 → 19），无 SQLite schema、Pixiv 接口或凭据落点变化。语言判定是启发式：拉丁语系之间（es / fr / de 等）不做跳过，中文简繁互转仍走翻译；它只用于省掉一次模型调用，不改变缓存与失效语义——切换目标语言不使已译页失效，用户可按需重译当前页。
