# ADR 0041：ruby 注释策略与标记不变量解耦

- 状态：已接受（细化 [ADR 0035](0035-whole-novel-agent-translation.md) 的约束冻结与
  [ADR 0038](0038-translation-review-convergence.md) 的修订收敛；不推翻既有决策）
- 日期：2026-10-29
- 关联 ADR：[ADR 0035](0035-whole-novel-agent-translation.md)、
  [ADR 0038](0038-translation-review-convergence.md)
- 规格：[SPEC](../SPEC.md) §4.3

## 背景

真实任务 `20261028235913-880714`（作品 14161953，4 块）在审查阶段不收敛并耗尽全部
调用预算（192 次）。日志与产物还原出三层规则互相矛盾：

1. **校验层（硬不变量）**：`validation.rs` 的 `ruby_markup` 检查强制要求译文中
   `[rb:` 标记数量与原文相等且结构合法（`[rb:原文>注音]`）；发布层固定把
   `[rb:A>B]` 渲染为 `A(B)`。
2. **扫描层（风格自拟）**：协调者扫描时把「注释策略」自拟为「ruby只取本体不注音」，
   该维度是自由文本，没有任何机制校验它与标记不变量是否相容。
3. **审查层（执行风格）**：审查者把「译文保留 `[[rb:...]]` 标记」判为
   `pass1_noncompliance`（major），甚至给出「删除标记」类修复建议——该修法必然被
   提交校验拒绝。

于是翻译子 Agent 两头挨打：按风格删注音 → 提交被校验拒绝；按校验保留标记（把读音
本地化为拼音）→ 审查判 major。主 Agent 反复 `revise_draft` → `dispatch_review`
约 8 轮（`revise_draft` 不消耗返工额度，也没有轮次上限），烧光预算后以
`budget_exhausted` 停在 `needs_attention`。审查者建议的修法本身无法通过校验，
说明提示词层与校验层对「标记必须保留」这一事实完全脱节。

结论：「注释策略」的可表达范围必须被限制在校验层允许的解空间内；修订循环也需要
确定性的收敛上界。

## 决策

### 1. 标记结构是唯一不变量，注释策略只约束读音内容

- `[rb:原文>读音]` 标记的数量、顺序、位置与结构由提交校验强制保持，任何角色不得
  提出删除、减少或改写标记结构的要求。
- 「注释策略」维度只允许描述 `>` 之后**读音内容**的处理方式：默认
  「读音本地化为目标语言拼音，不保留日文假名读音」，冻结策略明示时「保留原读音」。
- 发布层维持 `A(B)` 渲染不变；读音是否保留由注释策略约束其内容（拼音 / 原读音），
  不提供「整段去注音」的发布形态。

### 2. 提交与冻结时机器归一化

- `validation.rs` 新增 `normalize_annotation_policy(style)`：识别注释策略中与标记
  不变量冲突的表述（「只取本体」「不注音」「删除标记」等模式表），命中时把该维度
  改写为规范值
  「保留 [rb:原文>读音] 标记结构，读音本地化为目标语言拼音；不保留日文假名读音」，
  并返回冲突说明。
- `submit_scan` 与 `freeze_constraints` 在入口调用归一化；命中时记
  `annotation_policy_normalized` WARN 日志（只含策略描述，不含原文）。归一化发生在
  落盘前，因此冻结约束里永远不会出现不可执行的注释策略。`style` 不是合法 JSON 时
  不触碰原值。

### 3. 提示词同步收窄

- `coordinator.md`：注释策略维度说明收窄为「只描述读音处理方式」，并声明冲突时按
  运行层归一化结果执行、不作为阻断项。
- `translator.md`：新增 ruby 专条——保留等量标记；读音按冻结注释策略本地化
  （默认拼音）；不删除、不合并标记。
- `reviewer.md`：`pass1_noncompliance` 与 `markup_preservation` 明确「存在标记本身
  不是违规」；只有读音内容违反冻结策略（如拼音策略下残留假名）才按目标语言纯净度
  记问题；修复建议不得提出删标记类修法，合规修法是只改写 `>` 后的读音。
- `SKILL.md` 两处 ruby 条款同步。

### 4. 修订收敛闸（`revise_draft` 轮次上限）

- `revise_draft` 不消耗返工额度的设计不变，但新增每块**定点修订轮次上限
  `REVISE_LIMIT = 4`**（常量，不进设置）：超过后工具以 `revise_limit` 拒绝并提示
  「改用 `dispatch_translation` 整块返工；同类问题反复出现说明约束本身冲突，应
  `reset_phase` 重做准备或上报人工」。
- 用户手动 `resume` 时与返工计数同批清空（暂停、取消、自动续跑不清）。
- 该闸只是止损上界：真正的解药是第 1、2 条——约束里不再出现不可执行的目标。

## 取代关系

不推翻既有决策。ADR 0035 的约束冻结流程、ADR 0038 的审查分级与按块返工额度继续
有效；本 ADR 收窄「注释策略」的可表达范围并给修订循环补上界。

## 后果

- **死锁消除**：冻结约束中不可能再出现与校验层矛盾的注释策略；即使扫描自拟出冲突
  表述也会在提交前被归一化，翻译子 Agent 不再面临「满足风格则拒收、满足校验则判违」
  的两难。
- **审查建议可执行**：审查者不再提出删标记类修法，读音问题有唯一合规修法（改写
  读音内容）。
- **修订有界**：单块连续 4 轮定点修订仍未收敛时强制升级，预算不再被无限
  修订—复审循环耗尽。
- **残余风险**：冲突表述靠模式表识别，措辞超出模式表的冲突描述不会被归一化；缓解
  手段是提示词收窄（第一道）与 `revise_limit` 上界（兜底）。读音本地化为拼音是
  默认值，用户若希望保留原读音需在确认阶段显式修改注释策略。
