# ADR 0031：多小说并行后台翻译与底栏任务选择

- 日期：2026-10-17
- 状态：已接受
- 关联：ADR 0017、0029、0030

## 背景

ADR 0017 为小说翻译选了「请求全局串行，避免设定覆盖和重复扣费」，当时翻译只服务
单个阅读器会话，串行是最省心的选择。ADR 0029 与 0030 把翻译做成后台续跑、
进度事件驱动的独立任务后，这条约束开始限制实际使用：用户在一本小说上发起翻译后
切到另一本继续读，第二本点「翻译」会拿到第一本的 promise（前端 join 不校验小说），
或者在后端全局锁上无声排队，底栏也只显示得下一个任务。

用户要求：**支持多个小说并行后台翻译**；底栏单个任务保持原样，多个任务时显示
「后台 N 个翻译任务正在进行」，点击向上浮出任务选择窗口。

## 决策

### 后端：锁粒度从全局降到按小说（`state.rs`）

`AppState.translation_lock: Mutex<()>` 替换为 `TranslationLocks`，两级语义：

- **按小说串行**：`novels: Mutex<HashMap<i64, Arc<Mutex<()>>>>`，`acquire(novel_id)`
  取该小说的槽位。同一小说共享设定集（`bible`）与页译文文件，两个任务同时写会互相
  覆盖、重复扣费，必须串行；不同小说互不相干，可真正并行。引用计数为 1 的槽位在
  下一次取用时回收，长时间运行不会累积空槽。
- **缓存清理门**：`maintenance: RwLock<()>`。每个翻译任务持读锁（多本可并存），
  `clear_cache(kind = "translation")` 取写锁——所以有任何一个翻译在途都清不掉，
  与 ADR 0027 的安全语义一致，但不再因为多小说并行而失效。用 `try_write` 立即失败，
  清理命令不阻塞。

缓存命中检查仍在锁内：同一小说的第二个任务不能在第一个任务写一半时读到该页。

`translation_lock` 旧字段删除，`maintenance_cmds` 与 `translation.rs` 同步改用新结构。

### 前端：store 从单任务改为按小说的任务表（`stores/translation.ts`）

- `active: TranslationActive[]`，每本小说最多一条；`activeFor(novelId)` /
  `doneFor(novelId)` 是阅读器与底栏共用的读取入口（别的小说仍不显示他人进度）。
- **不同小说立即并行**：`begin` 按 `novel_id` 取各自的请求链，互不阻塞。
- **同一小说排队**：`chains: Map<novelId, Promise>` 把同小说的多次 `begin` 串成链，
  后一页在队尾顺序执行。它们在后端本来也要抢同一把小说锁，前端先排队可以让浮窗
  如实显示「排队等待中」而不是让后端静默等待。
- **同一小说同一页 join**：`inFlight: Map<"novelId:page", Promise>`，重复点击不重复请求。
- 进度事件按任务自增 `id` 定位到发起它的那份快照，多小说并行时不会互相改写进度条。
  这正是旧实现 `applyEvent` 直接改「当前 active」的隐患。
- 完成快照改为保留最近 8 条的数组（`dones`），每本小说各自一条，不再被后一本覆盖；
  失败记录同样改为数组（`errors`），`consumeError(novelId, page)` 语义不变。

### 界面：底栏单/多任务两种形态（`DownloadStatusBar.vue`）

- **0 个**：不占位（不变）。
- **1 个**：与既有样式完全一致——`翻译中：《title》第 N 页`，点击直接回到该小说。
- **≥2 个**：显示 `后台 {N} 个翻译任务正在进行`（≤640px 为 `{N} 个翻译中`），
  点击在底栏上方浮出 264px 任务选择菜单。菜单条目为小说标题 + `第 N 页 · 阶段 · 已用`，
  每行带 8px primary 状态点；选中直接跳到该小说页并自动展开翻译浮窗（沿用 ADR 0029
  的挂载即展开规则）。
- 菜单复用项目既有浮层配方：`surface-container` 底、`--radius-control` 圆角、
  唯一合法轻阴影 `0 4px 12px rgb(0 0 0 / 18%)`、透明遮罩点击外部关闭、Esc 关闭并
  焦点回到入口、打开焦点进入菜单。**不新增动效**（离场过渡会在无头渲染与
  `prefers-reduced-motion` 下留下残影；项目目前唯一的自定义循环动效仍是摘要 marquee）。
- 计数入口 `flex: none`，整句完整显示、由左侧下载进度区让位。**不要用百分比 `max-width`**：计数入口的父容器宽度本身由内容决定，百分比基准互相牵制，会把固定的短句压成「后台 2 ...」。

## 影响

- 同一小说的多页仍严格串行，语义没有变松；多本小说并行会同时占用模型服务配额，
  是否接受由用户的模型服务决定（本项目不额外限流，符合 ADR 0017「不自动重试、
  不替用户省钱」的既有立场）。
- 进度事件流协议（ADR 0029/0030）与 `novel_translate_page` 签名不变，前后端契约无破坏。
- `/tests/translation-tasks.html` 覆盖并行、排队、join、事件隔离与底栏两种形态；
  `state.rs` 单测覆盖并发语义与清理门。
