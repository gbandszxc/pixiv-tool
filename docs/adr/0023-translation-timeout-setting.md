# ADR 0023：小说翻译单请求超时可配置（默认 10 分钟）

- 日期：2026-10-04
- 状态：已接受

## 背景

ADR 0017 把小说翻译的单请求超时写死为 180 秒，ADR 0020 又明确「180s 超时…不变」。
用户反馈该默认值太短：两轮翻译每轮都是一次完整生成请求，慢模型（带思考/长推理）或
长页面经常在 3 分钟内拿不到响应，只能靠调低思考深度绕过；而超时值对用户不可见、不可调。

## 决策

- 新增设置键 `translation_timeout_seconds`（整数秒），**默认 600（10 分钟）**，
  合法区间 30~3600，设置弹窗「小说翻译 · 服务连接」用数字输入配置；
  保存时 bool / 非整数 / 越界一律拒绝（"翻译超时时间必须是 30~3600 秒之间的整数"）。
- 手改 `settings.json` 写入区间外的值（含 0 与负数）在加载期回落默认，
  对齐既有 `translation_api_format` / 缩略图档位的加载回落做法；使用处再兜底一次
  `clamp`，避免 0 秒让请求立刻失败。
- 超时语义：超时是**单次模型请求**的上限（一页通常两次请求，各自计时），
  不是整页或整册的预算；其余约束（全局串行、响应最大 4MB、不自动重试、
  两轮流程与共享设定集）全部不变。
- 超时错误文案改为报出**实际生效的秒数**（如「翻译请求超时（600 秒），可降低思考
  深度或调大设置里的翻译超时」），不再写死 180。
- 探测契约 `TranslationProbe` 增加可选字段 `timeout_seconds`（缺省 600，
  使用前同区间兜底）：「检测可用」是一次真实生成请求，按草稿值计时；
  「获取模型列表」是元数据端点，固定 30 秒不变。
- 该设置只影响应用发出的 HTTP 请求等待时长，不改 pixiv 抓取侧的任何超时
  （任务等待仍是 `max_wait_seconds`）。

## 影响

设置白名单 20 → 21 键，无新增 IPC 命令、无 SQLite schema 变化、无凭据落点变化；
老配置缺键取默认 600，不需要迁移脚本。上限 1 小时意味着单页翻译最坏耗时为
「2 × 超时 + 重试」，界面中的进度阶段（queued/prepare/translate）不变，
用户取消仍通过任务/页面级中断生效。若后续要按小说或按页覆盖超时，
应扩展本 ADR 而不是再写死常量。
