## 1. 目标与已确认边界

将现有「单个 Pixiv 阅读页、准备与翻译两轮请求」升级为完整 smart-translator 流程，解决长输入、长输出、审查与局部恢复问题，同时提供可供后续功能复用的极简通用 Agent 内核。

| 项目 | 决定 |
|---|---|
| 基础库 | 采用 Rig，小内核加应用运行管理层；以已核实的 0.45.0 稳定版为集成验证起点 |
| 工具链 | 一步升级到近期稳定版 Rust 1.99.1，见 §12；不贴着 Rig 的 1.97.1 下限升级 |
| 运行拓扑 | Tauri 单进程内使用 Tokio 驱动；不引入本地 HTTP 服务、固定端口或额外后端进程 |
| 工具 | 分块、术语合并、译文合并、质检汇总、阶段清理由 Rust 实现；不附带或调用 Python |
| 翻译任务单位 | 一篇完整 Pixiv 小说作品，包含全部阅读页；系列内其他作品各自独立 |
| 模型 | 主 Agent、翻译与审查子 Agent 共用现有服务、协议、模型和 Key，独立上下文及工具权限 |
| 资源 | 仅加载应用内置的 skill、参考资料、系统提示词和角色定义；无本机覆盖目录 |
| 动态加载 | 根据任务和阶段在运行时按需装配内置资源，不将全部资源一次性塞入上下文 |
| 系统提示词 | 先提供可替换的占位资源；运行约束和工具契约仍需完整，不能依靠空提示词保证执行 |
| 术语确认 | 默认自动按推荐术语与风格继续；用户启动前可选择先确认 |
| 产品入口 | 只改现有翻译按钮浮层；确认、预览、问题与恢复都在该浮层，无通用聊天页面 |
| 恢复 | 有限自动重试、缩块、定向返工及检查点恢复；推荐参数可手动调整 |
| 设置 | 渐进展示：一级常用设置，二级高级设置；不在首屏铺开参数表 |
| 日志 | 精简且易定位，区分并行小说与重译运行，显示阶段摘要及压缩、重试、恢复等关键事件 |
| 持久化 | 全部属于现有翻译缓存，跟随所属小说翻译任务一起清除，不留孤儿中间产物 |
| 首版不包含 | MCP、自由对话、外部插件、任意 shell、系列批量翻译、跨作品共享术语 |

## 2. 现状与接入依据

以下是本次只读核验的现状，实施前应再次核对行号与接口：

- `src-tauri/src/translation.rs::translate_page_flow` 当前按页工作，单页 120KB、整篇原文 8MB 上限；不是按实际模型 token 能力切块。
- `source_lines` 与 `validate_translation` 使用每个阅读页的原始零起行号关联译文。合并 Markdown 不能直接替代该契约。
- `frontend/src/stores/translation.ts` 当前持有长时间 invoke、前端队列和跨页状态；新运行状态需要由后端任务管理器持有。
- `commands/maintenance_cmds.rs::cache_path("translation")` 指向 `data/translations`；现有统计与清理均递归遍历该目录。
- `clear_cache("translation")` 使用 `TranslationLocks::try_block_maintenance` 排斥在途翻译；`frontend/src/api/maintenance.ts` 清理成功后派发 `pixiv-tool:translation-cache-cleared`。
- `read_logs` 当前读取 `app.log` 末尾 64KiB／最多 200 行；维护页已有大小统计、轮询和日志清理，不应另建一套独立日志目录与清理入口。
- `DESIGN.md` 规定翻译浮层基准宽 384px，复用 Material Web、现有 token、轻阴影、焦点返回与 reduced-motion 规则。
- 仓库目前声明 Rust 1.88；本机 MSVC 工具链实测为 1.98.1。本文提出 1.99.1 目标，不表示已经升级。

## 3. 领域模型与架构分层

### 3.1 术语

| 名称 | 定义 |
|---|---|
| 翻译任务 Job | 对一篇作品、一个原文版本、一个目标语言和固定资源／配置快照的处理 |
| 阅读页 Page | Pixiv `[newpage]` 分隔的页面，仅决定阅读展示 |
| 分块 Chunk | 为模型输入、输出预算和语义边界切出的处理单元 |
| 子任务 Subtask | 某个角色对指定输入集合执行的一次有边界的工作 |
| 产物 Artifact | 原文、准备结果、译文、质检记录、会话等持久化资源 |
| 检查点 Checkpoint | 能够恢复进度、依赖版本和未完成工作的提交记录 |
| 约束版本 | 已冻结的术语、风格及用户确认结果的版本 |
| 缓存拥有者 | 承载一个 Job 的目录及 manifest；拥有全部中间产物与会话生命周期 |

### 3.2 模块职责

```text
现有阅读器 / 翻译浮层 / 设置 / 后台状态栏
                     │ Tauri IPC
                     ▼
小说翻译服务
  原文页行映射 · 翻译任务身份 · 阅读器结果投影
                     │
                     ▼
通用 Agent 运行层
  任务与会话 · 内置资源 · 子任务与取消
  预算与压缩 · 统一恢复策略 · 检查点与事件
                     │
                     ▼
Rig：模型适配 / 流式响应 / 工具调用循环
              │                     │
       通用 Rust 工具         翻译 Rust 工具
       资源及产物访问         分块 / 聚合 / 校验
       子任务派发与等待       合并 / 质检 / 重置
```

通用内核不依赖 Pixiv、Pass 编号或人物译名。翻译服务负责把业务资源注入通用运行层，并实现缓存存储接口。未来其他功能自行提供内置任务定义、工具及缓存拥有者，不把新功能数据混进翻译目录。

主 Agent 根据 skill 决定扫描、翻译、审查与返工；Rust 工具处理确定性操作，并拒绝不满足前置条件的阶段提交。模型声明完成后仍必须校验任务完成条件。

建议目录职责（实施时可随已有命名调整）：

```text
src-tauri/src/agent/
  runtime / scheduler / context / resources / recovery / events / storage
src-tauri/src/translation/
  service / source / tools / artifacts / validation
src-tauri/resources/agent/
  prompts/                 # 基础系统提示词占位与摘要模板
  agents/                  # coordinator / translator / reviewer
  skills/smart-translator/ # 适配后的 SKILL.md 与 references
```

资源随应用打包或编译嵌入，不依赖源码仓库绝对路径。每个 Job 固定资源内容 hash、配置版本和已用资源列表；重启后必须验证这些版本仍可用，不能静默用新 skill 续跑旧任务。

## 4. Agent 循环、工具与子任务

### 4.1 循环

使用三协议原生工具调用，不解析模型正文中的伪工具指令：

1. 读取任务检查点，按权限和阶段装配上下文。
2. 检查输入、输出、轮次、任务调用总预算，必要时压缩。
3. 通过 Rig 流式请求模型，归一化正文、工具调用、可展示思考摘要、用量和结束原因。
4. 校验完整工具参数后执行，产物提交与检查点持久化。
5. 返回精简工具摘要，继续循环或校验最终完成条件。

模型适配必须保留现有三协议、URL 校验、凭据存储、代理感知、opencode 会话头、思考参数归一化与错误脱敏能力。Agent 流的正常终态还包括协议对应的工具调用结束原因，不能只沿用旧翻译的 `stop/end_turn` 判据。保留协议要求的 tool call ID、工具结果配对、推理签名或不透明续传字段；不把这些字段作为普通文本摘要后丢弃。

### 4.2 Subagent

- 通过 Agent 工具启动独立子会话；主 Agent 向子 Agent 委派工作，默认一层，不允许翻译／审查子角色继续派生。
- 每次委派显式传递原文块、前后文、约束版本、输出归属与角色定义，不复制完整父会话。
- 子任务输出完整产物；回传父会话的仅为状态、摘要、产物引用和用量。
- 主 Agent 等待时不持有模型请求许可；压缩请求同样使用全局模型请求闸门。
- 全局并发控制实际模型请求，并按小说公平调度，防止一本长篇占满所有槽位。
- 取消传播到父子任务、请求流及退避等待；写盘提交阶段保持原子性。
- 一次任务恢复不会清零累计预算、重试／返工记录。

### 4.3 Rust 工具

| 工具族 | 职责 |
|---|---|
| 加载资源 | 根据 ID 加载内置 skill、参考资料和角色定义；不访问任意本机路径 |
| 读取／提交产物 | 按范围读取；校验 schema、归属、版本、长度后幂等提交 |
| 派发／等待子任务 | 批量派发、限流、聚合摘要、获取状态、传播取消 |
| 准备翻译任务 | 解析原文、稳定页行片段 ID、语义切分、邻接上下文及 manifest |
| 聚合准备结果 | 汇总术语与风格，处理别名／译名冲突，冻结约束 |
| 合并译文 | 覆盖率、重复、顺序、页行映射与版本校验；生成阅读器投影及合并稿 |
| 汇总质检 | 校验审查记录、汇总问题、识别受影响块和整体复核状态 |
| 阶段重置 | 按依赖使旧结果失效；保留有效上游，不通过自由删除破坏 manifest |

工具按 Job 和调用标识幂等执行。模型没有修改检查点、预算或任务状态文件的自由写权限。新工具由 Rust 注册，skill 只能调用角色已开放的工具。

## 5. smart-translator 适配与翻译流程

来源为 `D:/ProjectSpace/skills/my-skills/common/smart-translator` 的较新版本；本机 Pi 安装版较旧。实施时将选定版本作为内置资源导入，保留来源信息和差异说明，核对可分发许可。项目运行时不依赖该本机路径。

适配保留 Pass 0～3、术语锁定、风格约束、逐块原文对照、整体复核及局部返工；将五个 Python 脚本替换为 §4.3 的 Rust 工具，工作目录替换为受控产物引用。

1. **Pass 0**：注册整篇原文，建立 page/line/segment 映射；按语义和双向 token 预算分块。
2. **Pass 1**：逐块扫描术语、人物关系、风格与对白；聚合并保存。既有锁定译名优先，冲突显式记录。先解决足以影响翻译的冲突，再冻结约束。
3. **确认分支**：默认自动继续；选中确认模式时在原浮层展示并允许修改术语和风格，点击「确认并继续」恢复。
4. **Pass 2**：按块派发翻译；只翻主块，邻接上下文不进入输出。完整响应经结构与覆盖率校验后提交草稿。
5. **Pass 3**：独立审查子会话对照原文、译文与冻结约束，检查漏翻、错翻、术语、风格、语气、语言与标记保真；定向修复或重译后复检。
6. **整体复核**：主 Agent 读取摘要并按章节、角色、关键边界抽样，形成全局记录。不能把全文重新塞回主上下文。
7. **发布**：满足块覆盖和质检条件后提交整篇完成结果。仍有问题则为部分完成／需要处理，不能冒充通过。

结构化译文保留原始页、行与片段 ID。超长单行可拆片段，最终按映射重组；Pixiv 图片、章节、ruby 和跳转等标记由原文解析层保留与校验，不依赖模型记忆。Markdown 合并稿是派生产物，不是双语阅读器唯一真相源。

已审查且完整覆盖某阅读页的结果可以提前发布到正文，草稿预览始终标识「尚未审查」。全局审查退回已发布块时保留旧可读版本，并标识有待修复，修订通过后原子替换。

原 skill 的日译中规则仅在该语言组合应用，其他目标语言仍按现有白名单和目标语要求工作；涉及官方译名查证但首版没有外部检索工具时，应记录依据不足，不虚构已查证事实。

## 6. 上下文与输出预算

压缩历史、限制工具结果和缩小翻译工作单元分别解决不同问题。压缩不能修复一次输出过长。

- 请求前强制满足：估算输入 token + 本次输出上限 + 安全余量 ≤ 模型上下文窗口。
- 输入包括系统提示词、工具 schema、历史、已加载资源、术语和原文；输出预算包含协议需要的思考额度。
- 可靠内置模型元数据优先；兼容端点未知时使用保守回退并标记估算，允许用户在二级设置填写真实能力。
- 估算使用可用 tokenizer；未知模型采用保守估算及安全余量，不宣称跨模型精确。
- 块预算同时考虑翻译膨胀、结构化编码开销，以及审查阶段同时包含原文和译文的更高输入成本。
- 超长术语表按相关项分片读取，另附全局风格及关键实体约束，避免每个子任务携带完整巨表；全局表保存在产物中。
- 工具读取与子任务回传设 token/长度上限，采用分页和产物引用，不用静默截断掩盖内容缺失。
- 参考内容与原文明确标记为数据；不能修改内置角色权限和工具规则。

压缩在完整请求／工具批次之间执行，保留调用与结果配对。摘要包含目标、确认约束、有效产物版本、进度、未决问题与下一步；原始记录不被摘要覆盖，压缩只改变后续请求的上下文投影。

压缩失败不丢弃原记录；超长历史分段摘要。失败或压缩后仍不满足预算时暂停该会话，不能无限「压缩—重试」。全量译文、术语、原文继续从产物读取，不依赖有损摘要还原。

## 7. 预设、预算与有限恢复

### 7.1 推荐参数

以下是项目推荐起始值，不宣称全部来自某个 SDK 的默认值。参考 OpenAI／Anthropic 默认两次重试、Pi 的预留输出和保留近期上下文、主流 Agent 的轮次上限机制；需在真实长篇样本校准。所有可编辑运行参数都放在 §8 的二级高级设置，一级仅显示「推荐／自定义」摘要。

| 参数 | 推荐值 | 调整／语义 |
|---|---|---|
| 全局模型请求并发 | 4 | 1～16，所有小说共用 |
| 单小说子任务并发 | 4 | 1～16，实际受全局上限限制 |
| 同时活跃小说 | 2 | 1～8，其余排队 |
| 自动网络重试 | 2 次 | 0～5，不含首次；统一由运行层执行 |
| 退避 | 1 秒起，指数增长，±25% 抖动 | 基础延迟 0.5～30 秒；抖动策略作为内置实现，不额外给用户一个字段 |
| 最大自动退避 | 120 秒 | 10～600 秒；尊重 Retry-After，要求更久则暂停，不提前重发 |
| 单请求超时 | 600 秒 | 30～3600 秒，沿用现有字段 |
| 质检返工 | 2 轮 | 0～5，包含修复及复检 |
| 超限细分深度 | 3 层 | 0～5，累计到当前块的父子谱系 |
| 工具参数／结构纠正 | 2 次 | 0～3；无效参数不执行副作用 |
| 单子任务模型轮次 | 24 | 4～128，一轮为一次模型调用，不含传输层重试 |
| 主 Agent 无进展上限 | 8 轮 | 3～32；没有新产物、有效派发或阶段推进时累计 |
| 未知模型上下文窗口 | 32,768 tokens | 可填写实际窗口，最小 16,384，最大按实现整数边界及验证规则限制 |
| 单请求输出上限 | 16,384 tokens | 向下收敛至模型能力和当前上下文；不能超过配置窗口 |
| 自动压缩触发 | 可用输入预算的 75% | 50%～90%，可用输入预算已扣输出和安全余量 |
| 保留近期历史 | 4,096 tokens | 可调；需容纳固定资源与摘要，否则继续缩减 |
| 摘要目标 | 2,048 tokens | 可调，受有效输入／输出预算约束 |
| 分块目标／字符上限 | 3,000／6,000 字符 | 可调；token 预算优先，目标≤上限 |
| 邻接窗口 | 前后各 600 字符 | 可调，不翻入正文 |
| 请求结果未知时自动重放 | 关闭 | 高级开关，提示可能重复计费 |
| 启动前确认术语与风格 | 关闭 | 一级常用设置及浮层本次覆盖 |

运行层维护整篇累计模型尝试预算：推荐自动公式 `32 + 16 × 初始分块数`，包含父子调用、摘要、传输重试和返工。它是防失控上限，不是预计调用量。二级设置允许选择自动或自定义正整数；手动恢复、再次派生或细分不重置预算。暂停时可显式追加预算并记录原因。

所有上下限还要做交叉验证；例如窗口预算不足以容纳输出、超长不可切结构或用户指定输出超过模型限制时，明确显示冲突而非盲目发请求。既有高级 JSON 归一化后也必须纳入预算，不能绕开预算器。0 值仅在明确表示关闭的参数允许，不能一概解释为无限。

### 7.2 恢复分类

| 情况 | 默认行为 |
|---|---|
| 明确未发送的连接失败 | 有限自动重试 |
| 可重试的限流、暂时性服务错误 | 遵守服务建议并退避；余额／配额耗尽等永久条件直接暂停 |
| 鉴权、余额、模型不存在、配置不兼容 | 暂停并提示修正设置 |
| 已发送且结果未知的断线／超时 | 保留现场；默认等待用户恢复，不自动重放 |
| 输入超限 | 压缩历史或细分对应工作单元，消耗恢复预算 |
| 输出截断 | 临时内容不提交完成态；缩块重做，不原样重复超限请求 |
| 工具参数／结构错误 | 精简诊断反馈模型，有限纠正 |
| 质检问题 | 仅修复／重译受影响块，复检；达到上限后需要处理 |
| 审核拒绝、预算耗尽、无法继续细分 | 保存现场并暂停；不规避审核或无限重试 |

Rig／传输层默认重试必须关闭或与运行层协调，防止次数相乘。不同恢复计数共享任务总预算。失败子任务不终止无依赖的其他块；已知不可恢复的全局配置错误则停止继续派发。

## 9. 精简且可定位的日志

### 9.1 复用现有日志管线

接入现有 `log`／`tauri-plugin-log` 和 `app.log` 轮转、读取、大小统计与清理。Rig 使用其他日志门面时接入统一桥接，避免重复初始化 logger；默认压低依赖库噪声。不得创建维护页清不到的 Agent 日志树。

所有 Agent 日志有固定事件名与可搜索键值：`novel`、`job`、`agent`，有分块／请求时追加 `chunk`、`request`、`attempt`、`phase`。Job 与请求标识在日志中使用足够长的唯一短 ID，并可映射浮层任务标识；同一本重译仍能区分。标题不作为主键，默认不记录小说标题或内容。

### 9.2 事件与密度

- **INFO**：任务排队／启动／终态；每个阶段起止与统计；子任务批次派发和完成摘要；确认／暂停／恢复／取消；缓存清理；每次压缩开始和完成。
- **进展摘要**：执行中按小说至多每 5 秒聚合一次，只在计数变化时输出，含已译、已审、待修、活跃数和耗时；阶段切换即时输出。每个步骤有进展结果，不逐 token 打日志。
- **WARN**：重试、截断、自动缩块、质检返工、预算临近或耗尽、结果未知、压缩失败；包含原因码和下一动作。
- **ERROR**：不可恢复的运行／存储失败，包含失败步骤、错误码与安全诊断。
- **DEBUG**：临时详细诊断才输出单个工具／请求／子任务的起止和耗时、输入输出长度、调用关联；不输出正文或工具原始参数。默认关闭，开关在二级诊断菜单，默认本次启动有效。

示例（正文为程序生成摘要，非模型输出原文）：

```text
INFO novel=123 job=8b57c120 phase=prepare event=phase_done chunks=30 terms=42 elapsed_ms=18420
INFO novel=456 job=d912f046 phase=translate event=progress translated=8/20 reviewed=0/20 active=4
INFO novel=123 job=8b57c120 agent=main event=compact_start context_est=24100 trigger=23040
INFO novel=123 job=8b57c120 agent=main event=compact_done before_est=24100 after_est=6900 elapsed_ms=3100
WARN novel=456 job=d912f046 chunk=0009 event=retry_scheduled code=rate_limit attempt=1/2 delay_ms=2000
WARN novel=123 job=8b57c120 chunk=0013 event=rechunk reason=output_limit depth=1 children=2
INFO novel=456 job=d912f046 event=resumed reused_chunks=8 pending_chunks=12
```

进展聚合器在阶段结束和任务终态主动 flush。限流重复错误在聚合摘要中累计，保留首次、策略变化和最终失败，避免并发重试淹没 200 行日志窗口。UI 逐帧预览独立于磁盘日志，不因降噪失去实时反馈。

错误保留现有脱敏诊断策略：安全的服务错误类别、code/type/param/request_id、必要且脱敏的 message；不记录请求体、生成正文、原文、API Key、Cookie、完整 URL、提示词或推理全文。控制字符压平，字段限长。压缩记录只含估算计数、耗时、保留范围与结果，不打印摘要正文。

## 10. 持久化归属、缓存清理与恢复

### 10.1 全部翻译产物共用拥有者

```text
data/translations/v2/<novel_id>/<job_id>/
  manifest.json           # 拥有者、输入/语言/资源版本、状态、计数
  settings_snapshot.json  # 不含凭据
  resources.json
  source/
  preparation/
  chunks/
  reviews/
  output/                 # 正式阅读器结果、合并稿
  sessions/               # 父子会话、压缩记录
  checkpoints/
  temporary/              # 流式及提交临时文件
```

原文、译文、摘要、会话、检查点、报告和临时文件全部落在所属 Job 内。Rig 的默认全局 memory／session 目录必须显式替换为受控存储，不能在 config、用户主目录或另一个 Agent 数据根下留下副本。全局索引原则上从 manifest 重建，首版不新增独立数据库表存储翻译产物引用。

通用内核通过宿主提供的存储接口工作；翻译宿主将其所有会话、摘要和临时写入绑定到同一缓存拥有者。全局日志只留下轮转诊断元数据，不包含可恢复小说内容，不作为翻译恢复产物。

### 10.2 清理语义

- `maintenance_info` 的 translation 分类包含旧版译文和 v2 全部产物；沿用递归统计，必要时说明「包含中间产物和恢复记录」。
- 现有 `clear_cache("translation")` 清除该分类全树；不能只清 output，遗留 sessions/chunks/checkpoints。
- 应用内若提供某本／某次译文删除，必须通过缓存拥有者操作删除对应 Job 根目录及其全部后代；不能实现成只删除最终译文文件。删除小说全部翻译则删除该小说下所有 Job。
- 正式结果与中间数据不跨拥有者共享文件或引用，避免删除一个 Job 破坏另一个 Job，或为共享资源引入孤儿回收问题。
- 用户导出到缓存外的译文是明确保存的文件，不受缓存清理影响；首版不因此新增导出入口。
- 未完成任务合法地没有正式译文，不能以「output 不存在」判断为孤儿。根据 manifest 的提交状态识别未完成、损坏和清理未完成目录。

### 10.3 互斥及防复活

保留既有翻译缓存维护读写门。运行／取消收尾／流式临时写盘期间持有使用许可；任一任务仍在使用缓存时，整类清理明确拒绝，不能边清边写。

暂停且已到检查点、等待确认、失败和已中断任务可以释放使用许可。之后执行缓存清理会删除其恢复数据，清理成功事件必须同时使后端恢复索引、前端任务快照、阅读器译文和预览失效。

恢复与清理共享同一门控：恢复先取使用许可并验证 Job 及缓存世代；清理独占期间禁止新任务创建／恢复。后台迟到回调携带拥有者和世代校验，已清理 Job 不得由保存回调重建目录。不能只监听前端清理事件而让后端仍持有可继续写入的对象。

单任务删除或阶段清理由受控删除意图／失效标记保证中断后可收尾，已失效拥有者不再可恢复；删除失败不得返回成功。启动或下次维护时识别并收尾清理残留，不把它们当可用任务。沿用路径校验及符号链接／junction 边界，不跟随到应用数据目录之外。

对人工删文件的情况，启动／读取时检测 manifest 与产物一致性：已标完成但 output 消失的任务标记缓存损坏，不根据旧摘要盲目恢复；清理动作按拥有者一起清除。不能误删仍在进行或等待确认的任务。

### 10.4 恢复与版本

- 同一小说同一输入版本和目标语言的重复启动加入现有 Job；重译创建新 Job，保留已读旧结果直到新结果通过。
- 每个产物记录输入 hash、约束版本及 schema 版本。流式写 temporary，完整结束与校验后原子提交。
- 重启将未结束状态转换为 interrupted，不自动请求付费模型；用户在浮层恢复。
- 准备约束修改时按依赖使相关译文与审查失效；计数和预览同步回退。
- 任务沿用配置快照，用户明确更新配置或追加预算时才改变，保留记录。
- 旧版缓存只读兼容，不能自动冒充新流程已审结果；同样由现有清理入口删除。

## 11. 任务状态、事件与 IPC 方向

状态与阶段分离：

```text
queued → running → completed
            ├→ awaiting_confirmation
            ├→ pausing → paused
            ├→ needs_attention
            ├→ cancelling → cancelled
            └→ interrupted
```

阶段为 prepare_source、prepare_constraints、translate、review、repair、global_review、publish。等待确认／暂停／需要处理可以在检查后恢复；完成条件由实际产物和审查状态决定。缓存被清除后，相关 Job 不再存在，不保留可点击恢复的幽灵条目。

后端为状态真相源：启动快速返回 Job ID；提供状态快照、当前小说结果、确认、暂停、恢复、取消及事件订阅能力。IPC 的最终名字、数量在实现阶段定稿并更新 SPEC 命令表；不在文档阶段伪报已注册命令。

事件携带 Job/小说/子任务/分块标识、递增序号、状态与计数；前端挂载采用快照加序号追赶，避免「先读快照再订阅」丢事件。高频增量节流，阶段、重试、压缩、终态及时发送。状态栏复用现有多小说任务选择入口；浮层只显示当前小说。

## 14. 验收标准

1. **长篇与对照**：多页、超长单行、Unicode、ruby、章节、图片等映射稳定；缺段／重复／错序不能发布。
2. **预算**：完整请求含工具定义与思考预算；输入／输出超限分别恢复；未知模型有保守回退；总预算不能被恢复和再派生绕过。
3. **子任务**：父等待不占槽，压缩也受闸门；多小说公平并发，无死锁、状态串线和文件覆盖。
4. **压缩**：多次压缩后保留任务约束和工具配对；摘要失败保留原记录；每次开始、完成、失败可在日志定位。
5. **协议**：三协议的增量工具参数、原生结束信号、推理签名／续传字段、截断、用量、错误与取消均有离线覆盖。
6. **恢复**：请求、工具提交、合并发布任一点中断；已完成操作不重复执行；结果未知不自动重放；不完整产物不冒充完成。
7. **质检**：只返工受影响块；达到上限显示未解决项；通过块与旧可读版本不被失败结果覆盖。
8. **设置分层**：一级看不到运行参数墙和原始 JSON；二级返回保留草稿；隐藏错误可定位；取消／保存／恢复推荐值行为一致。
9. **日志定位**：两本并行小说及同本重译运行可按 novel/job 过滤；每阶段有摘要，压缩／退避／缩块／返工／恢复有事件；无逐 token 刷屏、原文或凭据泄露。
10. **缓存全清**：现有清理入口使旧译文和 v2 原文／分块／会话／压缩／检查点／临时文件全部归零；app.db、图片、凭据、配置与外部用户文件保留。
11. **拥有者删除**：删除某次翻译同时删除其所有中间产物；清理中断后可收尾；不遗留可恢复索引、目录或跨拥有者悬挂引用。
12. **清理竞态**：运行中拒绝清理；暂停／确认任务清理后不可恢复；迟到回调不重建缓存；创建／恢复与清理门控严格互斥。
13. **UI**：浮层关闭不取消，重回页面状态正确；宽窄／深浅、长文、键盘、focus、disabled、loading、error、reduced-motion 均通过。
14. **构建**：Rust 1.99.1 在开发脚本、CI 与 manifest 一致生效；Windows MSVC check/test/build 通过，macOS／Linux 按可用环境验证并记录未验证项。
